ACMI Agent Communication Standard v1.1

Author: Maya Reyes · Version: 1.1 · Modified: 2026-05-20
1. Overview 2. Event Structure 3. Correlation IDs 4. Namespace Registry

1. Overview

The ACMI Communication Standard defines how agents, threads, and systems within the fleet ecosystem emit and consume structured timeline events. Every event flows through the acmi:event namespace and carries a uniform schema that ensures cross-agent traceability.

This standard applies to all ACMI-compatible agents deployed on the fleet edge (vessels 1-12), backend orchestrators, and developer tooling. Compliance is enforced at the event gateway layer.

Why a Standard?

Without a shared schema, events from Agent LL-7, the OTA pipeline, and manual operator actions would be incomparable. The standard guarantees that any consumer — human or agent — can reconstruct the full chain of causality for any fleet operation.

2. Event Structure

Each ACMI event is a JSON object with the following top-level keys:

{ "namespace": "agent|thread|work|system", "id": "<entity-id>", "source": "<agent-name|system>", "summary": "<human-readable description>", "kind": "<event-kind>", "correlationId": "<cross-session-token>" }

The kind field is a controlled vocabulary. Standard kinds include handoff-complete, step-done, decision, alert, sync-failure, and deployment.

3. Correlation IDs

Correlation IDs link events across namespaces and sessions. They follow a flattened camelCase convention: otaPush-20260522-v2_4 or syncFail-vessel7-1743. Every event that participates in the same logical operation MUST carry the same correlationId.

When an agent spawns a sub-task, it MUST propagate the parent's correlationId and append a segment. Example: otaPush-20260522-v2_4-hotfix.

4. Namespace Registry

Four top-level namespaces are defined:

agent — Individual ACMI agent timelines (LL-7, Maya's dev agent, etc.)
thread — Multi-agent conversation and coordination threads
work — Cross-session work items (tasks, projects, OTA pushes)
system — Infrastructure events (deployments, health checks, scaling events)

Each namespace stores its events under acmi:{namespace}:{id}:timeline. Consumers use the acmi_cat tool to merge multiple timelines into a single sorted view.
