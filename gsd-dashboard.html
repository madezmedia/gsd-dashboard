ACMI Fleet Architecture v1.3
Spec · Updated May 20, 2026 · 1,240 words · v1.3

Overview

The ACMI (Agentic Coordination & Memory Infrastructure) protocol defines how autonomous agents communicate, share state, and coordinate across sessions. It is built on three primitives: Profile (permanent identity), Signals (mutable current state), and Timeline (append-only event history).

Architecture

Each agent in the fleet maintains its own three-slot storage indexed by entity ID. The fleet orchestrator reads the global timeline stream and merges events across agents to produce a unified view. This pattern ensures no single agent can corrupt another's state.

Storage Backend

All ACMI data lives in Upstash Redis (loved-platypus-102968 instance). Keys follow the pattern acmi:{namespace}:{id}:{slot}. The MCP server wraps REST API calls to provide a consistent interface across agents.

Communication Standard v1.1

Every timeline event carries: source (agent name), kind (event type), correlationId (trace across agents), and summary (human-readable description). Events are logged via the acmi_event MCP tool.

Fleet Health

The fleet orchestrator monitors agent engagement via heartbeats, tracks stalled projects (>72h silence), and escalates blockers to the human operator. All telemetry is surfaced in the Command Center dashboard.
